## Minor

### 🟡 Resend swallows failures and always claims success, `app/(auth)/sign-up/sign-up-form.tsx:57`

**Problem**: `resend()` awaits `sendVerificationEmail` but ignores its error and unconditionally sets `resent` to true ("A fresh verification link is on its way"), even when rate-limited (`RATE_LIMITED`) or offline.

**Why it matters**: The user is told an email is coming when none was sent, and the one place the UI handles `RATE_LIMITED` everywhere else (sign-in, sign-up, forgot) is missing here. Low frequency, but a straight-up wrong success message on an auth path.

**Suggested fix**: Capture the error from `sendVerificationEmail` like `onSubmit` does, surface `friendlyMessage`, and only set `resent` on success.

### 🟡 `getAdminUser` logs a denial on every benign check and has no callers, `lib/auth-helpers.ts:128`

**Problem**: `getAdminUser` writes an `ADMIN_ACCESS_DENIED` audit row whenever the caller is not an admin, and nothing in the tree calls it. If a future page uses it for conditional rendering (its obvious purpose), every ordinary student visit will mint a false "attack" audit event.

**Why it matters**: Audit log integrity — AC-5's audit trail becomes noise, and real denied-access attempts get harder to spot. Currently latent since it is unused.

**Suggested fix**: Either remove it until needed, or split the read (`readAdminUser`-style, no logging) from the logging guard (`requireAdmin`), so conditional checks don't write audit rows.

### 🟡 `requireAdmin` reads the session and user row twice per request, `lib/auth-helpers.ts:106`

**Problem**: `readAdminUser()` already fetches the session and the user row; on the deny path `requireAdmin` fetches both again solely to fill the audit `role` field.

**Why it matters**: Every denied (and, via `readAdminUser`, every allowed) admin request pays 2x session + 2x DB reads. The spec accepts one DB role read per admin request, not two. Small but on every admin hit.

**Suggested fix**: Have `readAdminUser` return the role (or null-reason) alongside the user so `requireAdmin` logs without re-querying.

### 🟡 Admin layout always audits `targetId: "/admin"`, `app/admin/layout.tsx:6`

**Problem**: The layout hardcodes `"/admin"` while AC-5 requires `targetId` to be the pathname. A denied hit on `/admin/users` (or any future nested route) is logged as `/admin`.

**Why it matters**: Audit granularity the spec explicitly requires is lost for every nested admin route. The unit test only covers the top-level path, so this drift is invisible.

**Suggested fix**: Pass the real pathname (e.g. `headers()`-derived path in the layout, or move the guard so each route supplies its own path).

### 🟡 `applyJoins` silently drops all but the first match on one-to-many joins, `lib/auth-adapter.ts:147`

**Problem**: Matches are keyed in a `Map` and a single row (or one-element array) is attached, so a join that legitimately returns several rows per key loses data without error.

**Why it matters**: Today's flows only exercise single-row joins (session→user), so this is latent — but the adapter presents a general `join` interface, and silent truncation is the worst failure mode for it.

**Suggested fix**: Group all matches per key and attach the full array for to-many relations; keep single-object shape only when the join config declares a singular relation.

### 🟡 Sort allowlist omits real timestamp fields, `lib/auth-adapter.ts:16`

**Problem**: `SORTABLE_FIELDS` lacks `session.updatedAt` (and `verification.updatedAt`) even though the schema has them, and `withSort` silently skips unknown fields — so a `sortBy: { field: "updatedAt" }` on sessions returns unordered rows instead of erroring.

**Why it matters**: Silent wrong-order results (e.g. "latest session" logic) rather than a loud failure. Latent today, cheap to close.

**Suggested fix**: Add the missing timestamp fields to the allowlist, or throw on unknown sort fields so misuse surfaces in tests.

## Strengths

- The route-layer pre-checks are exactly right: 429 `RATE_LIMITED` without delegating, 410 `TOKEN_EXPIRED` without echoing the token, 403 `ACCOUNT_INACTIVE` without echoing the password — and tests assert the non-leakage.
- The adapter is genuinely well-tested (operator matrix, AND/OR folding, unfiltered-update guard, transaction path) against a faithful ORM fake, and it correctly returns counts from `updateMany`/`deleteMany`.
- Email normalization is done in two places that agree (route lowercases for lookup/rate-limit key, `user.create.before` hook lowercases for storage), and the case-insensitive adapter path is covered.
- Role freshness and deactivation are enforced at every layer (route pre-check, `getCurrentUser`, `requireAdmin` DB re-read), matching the spec's anti-stale-role rule; the Arcjet `accountEmail` characteristic has a regression test pinning the earlier fault-fix.
- Test signal is strong for a tracer bullet: config assertions, helper unit tests with mocked navigation/headers, route tests with mocked Arcjet/Prisma, component tests, and a Mailpit-backed Playwright suite covering AC-1 through AC-3. Sampled run (auth-helpers, auth-client, route: 23 tests) is green.
